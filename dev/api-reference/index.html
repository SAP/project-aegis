    API Reference¶

    Guard¶

    aegis.Guard(name, normalize=False) ¶

    Pure validation engine with a fluent .use() API.

    All registered validators run concurrently on each validate() call. Input is a plain string or a :class:ContentView; validators receive the view (call view.render() for the flattened text). The engine never touches transport parts — adapters map parts to a view.

    Parameters:

    Name Type Description Default
    name str

    Identifier for this guard (used in spans / logs).

    		 required
    normalize bool | NormalizationConfig

    Controls guard-side normalization applied to each content item's value once before fanning out to validators. Accepts a bool (convenience alias) or an explicit :class:NormalizationConfig. True applies the engine profile (:meth:NormalizationConfig.for_engine — NFKC-folded, variation-selector-stripped, homoglyph-mapped); False applies none; a NormalizationConfig applies exactly the strategies it declares. Validators see the canonical form; the caller's original input is never mutated and the normalized form does not escape via GuardResult. Defaults to False so multilingual inputs round-trip untouched. Enable for security-sensitive detection over untrusted input (homoglyph / Unicode-bypass protection).

    		 False

    aegis.GuardResult(results=list()) dataclass ¶

    The combined outcome of a :meth:Guard.validate run.

    Guard runs its validators concurrently and collects every verdict here. Use has_failures to gate on the run as a whole, and failures to report the specific rejections.

    Attributes:

    Name Type Description
    results list[ValidationResult]

    One :class:PassedResult or :class:FailedResult per registered validator, in registration order.

    has_failures property ¶

    Return True if any validator rejected the input.

    failures property ¶

    Return just the failing results, preserving registration order.

    MutationGuard¶

    aegis.MutationGuard(name) ¶

    Sequential mutation pipeline over a :class:ContentView.

    Validators run in registration order. Each sees the current view (so a later validator sees earlier mutations), detects via validate, and returns whole-item ItemEdits via mutate. The engine rebuilds the view after each, so item count and order are preserved. Input is a plain string or a ContentView — the engine never touches transport parts (adapters map parts ↔ view).

    use(validator) ¶

    Register a mutation validator. Validates protocol at registration time.

    aegis.MutationGuardResult(results=list(), was_mutated=False, output=None) dataclass ¶

    The combined outcome of a :meth:MutationGuard.validate run.

    Use has_failures to gate on the run as a whole, and failures to report the specific rejections.

    Attributes:

    Name Type Description
    results list[ValidationResult]

    Validation results from each registered validator, in registration order.
    was_mutated bool

    True when the mutated output differs from the input content. This tracks the content actually changing, not merely that a validator emitted edits — a no-op edit (a replacement whose value equals the original) leaves was_mutated False. Inspect output for the mutated content.
    output str | ContentView | None

    The final content after all mutations, mirroring the input type — a str when validate was called with a str, otherwise a :class:ContentView (same item count and order as the input). For the view case, call output.render() for flattened text, or map it back onto your transport's parts in your adapter.

    has_failures property ¶

    Return True if any validator rejected the input.

    failures property ¶

    Return just the failing results, preserving registration order.

    Mutation Types¶

    aegis.ItemEdit(id, value) dataclass ¶

    A whole-item replacement: swap the item with this id for a new value.

    This is the unit a mutation validator's mutate returns. The engine applies it through :meth:ContentView.rebuild, which addresses the target item by id and leaves every other item untouched.

    Attributes:

    Name Type Description
    id str

    The :attr:ContentItem.id of the item to replace.
    value str

    The full replacement text for that item.

    aegis.ContentView(items) dataclass ¶

    The whole message a validator inspects: its parts, in order.

    A validator reads the parts through items (each a :class:ContentItem) or as one flattened string through :meth:render. A mutation validator then returns :class:ItemEdit values addressed by ContentItem.id, which :meth:rebuild applies to produce the mutated view.

    render() ¶

    Return every part's value joined by newlines, in order.

    Use this when a validator reasons over the whole message at once rather than part by part — for example, matching a pattern that may span parts.

    Note: parts are joined with "\n" regardless of how the transport actually separated them, so render() is for inspection, not for reconstructing the exact original wire format.

    def rebuild(self, edits: list[ItemEdit]) -> ContentView:
    """Apply ``edits`` to this view, returning a new view with identical item count and order.

    Each :class:`ItemEdit` replaces one item's ``value`` by ``id``. Items that are not
    addressed pass through unchanged, so cardinality and order hold by construction. An
    edit whose ``id`` matches no item raises :class:`MutationError`.
    """
    ids = {item.id for item in self.items}
    new_values: dict[str, str] = {}
    for edit in edits:
        if edit.id not in ids:
            raise MutationError(f"edit references unknown item: {edit.id}")
        new_values[edit.id] = edit.value  # last edit wins on a repeated id

    return ContentView(
        items=tuple(
            replace(item, value=new_values[item.id]) if item.id in new_values else item for item in self.items
        )
    )

    aegis.ContentItem(id, type, value) dataclass ¶

    One typed piece of content as seen by a validator.

    Attributes:

    Name Type Description
    id str

    Engine-assigned handle for this part, used to address edits back at it in :class:ItemEdit. Stable for one guard run — the same id identifies this part across validate, mutate, and any later validators in the pipeline. It is not a durable identifier: a new run reassigns ids, so do not store an id and reuse it across runs.
    type ContentType

    The content modality — :attr:ContentType.TEXT today, with other kinds (image, audio, ...) planned.
    value str

    The content payload (text today).

    aegis.MutationError ¶

    Bases: Exception

    Raised when edits cannot be applied to the view.

    The engine guarantees the mutated output has the same parts, in the same order, as the input. An :class:ItemEdit whose id matches no part would break that guarantee, so :meth:ContentView.rebuild raises this instead of silently dropping or misplacing the edit.

    Result Types¶

    aegis.PassedResult(validator_name='', details=dict()) dataclass ¶

    The outcome of a validator run that accepted its input.

    Frozen on purpose: a result must never change after construction, which also keeps it consistent with the other frozen result types (FailedResult, ContentItem, ContentView).

    Attributes:

    Name Type Description
    validator_name str

    Name of the validator that produced this result. A validator leaves this empty; the engine fills it in with the validator's name so a caller can tell results apart.
    details Mapping[str, Any]

    Optional structured data the validator chose to attach (for example, a count of what it checked). Free-form and safe to ignore — the engine does not read it.
    Example

    PassedResult().validator_name # engine fills this in later ''

    aegis.FailedResult(error_message='', error_code='', validator_name='', details=dict()) dataclass ¶

    The outcome of a validator run that rejected its input.

    Frozen for the same reasons as PassedResult: the error_code and error_message a caller acts on must stay exactly as the validator produced them, and it keeps the result types consistent.

    Attributes:

    Name Type Description
    error_message str

    Human-readable explanation of what failed, safe to show to the caller.
    error_code str

    Machine-readable reason for the rejection, for callers that branch on the failure kind rather than parse the message.
    validator_name str

    Name of the validator that produced this result. A validator leaves this empty; the engine fills it in with the validator's name.
    details Mapping[str, Any]

    Optional structured data the validator chose to attach. Free-form and safe to ignore — the engine does not read it.
    Example

    result = FailedResult(error_message="Email found in input.", error_code="PII_DETECTED") result.error_code 'PII_DETECTED'

    A2A Wrapper¶

    aegis.a2a.GuardedAgentExecutor(executor, input_config=None, output_config=None) ¶

    Bases: AgentExecutor

    Wraps any AgentExecutor with automatic input/output guardrails.

    The inner executor's execute() and cancel() methods are unchanged — guardrails are applied transparently via wrapped context and event queue.

    Pass :class:InputGuardConfig and/or :class:OutputGuardConfig to configure each phase independently::

    GuardedAgentExecutor(
    executor=my_executor,
    input_config=InputGuardConfig(
        guard=my_input_guard,
        on_fail="I'm unable to help with that request.",
    ),
    output_config=OutputGuardConfig(
        mutation_guard=my_output_mutation_guard,
    ),
)

    on_fail in each config accepts a static value or a callable. Return False explicitly to allow through; None (implicit return) is treated as rejection/suppression (fail-close default).

    Conversation history for context-aware validators (e.g. ScopeCheck) is supplied through :attr:InputGuardConfig.history_provider — an async callable that returns prior turns from whatever backend the user chooses (SAP Agent Memory, context.related_tasks, Redis, etc.). Aegis calls the provider once per request and stores the result on GuardMetadata.conversation_history. See examples/history_provider_*.py for reference implementations.

    aegis.a2a.guarded(input_config=None, output_config=None) ¶

    Decorator that wraps an AgentExecutor's execute() with guardrails.

    A thin wrapper over :class:GuardedAgentExecutor — the decorated class's original execute() is preserved and called through the same guard pipeline as the wrapper, so there is no duplicated logic.

    Usage::

    @guarded(
    input_config=InputGuardConfig(
        guard=my_input_guard,

    def guarded(
    input_config: InputGuardConfig | None = None,
    output_config: OutputGuardConfig | None = None,
):
    """Decorator that wraps an AgentExecutor's ``execute()`` with guardrails.

    A thin wrapper over :class:`GuardedAgentExecutor` — the decorated class's
    original ``execute()`` is preserved and called through the same guard
    pipeline as the wrapper, so there is no duplicated logic.

    Usage::

        @guarded(
            input_config=InputGuardConfig(
                guard=my_input_guard,
                on_fail="I'm unable to help with that request.",
            ),
            output_config=OutputGuardConfig(
                mutation_guard=my_output_mutation_guard,
            ),
        )
        class MyAgentExecutor(AgentExecutor):
            async def execute(self, context, event_queue):
                # original logic here — called after guards pass
                ...

    ``on_fail`` in each config accepts a **static value** or a **callable**.
    Return ``False`` explicitly to allow through; ``None`` (implicit return)
    is treated as rejection/suppression (fail-close default).
    """

    def decorator(cls):
        original_init = cls.__init__
        original_execute = cls.execute  # captured before cls.execute is replaced

        def new_init(self, *args, **kwargs):
            original_init(self, *args, **kwargs)
            self._guarded_executor = GuardedAgentExecutor(
                executor=_OriginalAdapter(self, original_execute),
                input_config=input_config,
                output_config=output_config,
            )

        async def wrapped_execute(self, context, event_queue):
            await self._guarded_executor.execute(context, event_queue)

        cls.__init__ = new_init
        cls.execute = wrapped_execute
        return cls

    return decorator

    speculative = False class-attribute instance-attribute ¶

    When True, run the detection guard in parallel with the agent.

    Normally the guard runs before the agent, so every request pays the guard's latency (LLM-based validators add ~0.8–2.6s). Speculative holdback starts the agent immediately while the guard validates concurrently, and holds the agent's output in a buffer until the guard passes:

    • Guard passes (~99%): the buffer is flushed to the user. The guard's latency was hidden behind the agent's own work.
    • Guard fails (~1%): the agent is cancelled and the buffer discarded — the user sees only the rejection, exactly as in sequential mode. No output ever reaches the user before the guard passes.

    Only applies when the agent can start on clean input — i.e. no input mutation_guard, or mutation_first=True. If a non-mutation_first mutation guard is configured, aegis silently falls back to sequential execution (:meth:GuardedAgentExecutor._should_speculate).

    Warning

    Read-only agents only. Enable speculative holdback only for agents with no external side effects at any point during execution — reads, computation, and LLM calls are fine, but no database writes, no state-mutating API calls, no file writes. On a failing verdict the agent is cancelled mid-execution; buffering hides its output but cannot undo an action already taken, so a write issued while speculating may be committed even though the request was rejected. Do not set speculative=True on write-capable agents.

    Cancellation safety is also required: on the failure path the agent is cancelled mid-execution, so the agent, its LLM/graph invocation, and any clients must unwind cleanly on CancelledError.

    Defaults to False — existing behaviour is unchanged.

    stream_lifecycle_events = False class-attribute instance-attribute ¶

    When True (and speculating), let non-content lifecycle events through the holdback buffer instead of buffering them.

    The agent's first emissions are usually a Task creation event and a TaskStatusUpdateEvent (e.g. an "Analyzing your request…" status). By default (False) aegis holds everything until the guard passes — strict non-leakage: the user sees nothing, not even a "working" status, before the verdict.

    Setting this True forwards those lifecycle events immediately for better perceived latency, while still buffering every TaskArtifactUpdateEvent (the actual answer). This is a deliberate, documented relaxation of strict non-leakage — enable it only when your pre-verdict lifecycle events carry no user or model content (e.g. a static status string).

    aegis.a2a.InputFailHook = bool | str | InputFailHookCallable module-attribute ¶

    Controls behaviour after input guard failures.

    Accepts a static value or a callable:

    Static values (decided at configuration time): - True: reject the task with all failure messages joined by "; ". - str: reject the task with this custom message. - False: continue execution (explicit opt-in to allow through).

    Callable (decided at runtime): - Called with (failures, context, event_queue). Both sync and async are supported. - Return value uses the same semantics as static values above. - None (implicit return) is treated as True (reject).

    Defaults to rejection — the safe default is to block. Return False explicitly to allow through.

    aegis.a2a.OutputFailHook = bool | str | OutputFailHookCallable module-attribute ¶

    Controls behaviour after output guard failures.

    Accepts a static value or a callable:

    Static values (decided at configuration time): - True: suppress the artifact (do not emit). - str: replace artifact text with this message before emitting. - False: emit the artifact as-is (explicit opt-in to allow through).

    Callable (decided at runtime): - Called with (failures,). Both sync and async are supported. - Return value uses the same semantics as static values above. - None (implicit return) is treated as True (suppress).

    Defaults to suppression — the safe default is to block. Return False explicitly to allow through.
