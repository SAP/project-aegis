    FormulaInjectionDetector¶

    Flag input that would begin a spreadsheet formula if written into a CSV/TSV cell (CSV injection).

    Description¶

    FormulaInjectionDetector is a deterministic, text-only, detect-only validator. It runs under Guard and reports a failure when a content item, written into a spreadsheet-imported cell (CSV, TSV, and the like), would begin a formula and execute when the file is opened — =cmd|'/C calc'!A0, =HYPERLINK(...). It never changes the content. Reach for it on input or model output that could later be exported to a spreadsheet.

    "CSV injection" (CWE-1236 / OWASP) is the common alias. The check is about a formula initiator at a cell's start, not about CSV structure, so the validator is named for the payload rather than the transport; CSV structural injection (forging columns/rows) is a separate concern.

    Guard runs its registered validators concurrently, so a failure here does not short-circuit or skip other validators.

    Obfuscation is decoded before detection¶

    Real payloads hide behind encoding layers, so each item is preprocessed before inspection: invisible/zero-width control characters are stripped, then URL-percent, HTML-entity, JavaScript \uXXXX/\xXX, and CSS \3C escapes are decoded repeatedly until the text stops changing (bounded). Without this, %3Dcmd or &#61;cmd would hide the leading =. Preprocessing does not NFKC-fold, so the full-width initiators ＝＋－＠ are matched explicitly. Both passes can be disabled via the constructor when the input's encoding is fully trusted.

    What it flags¶

    For each cell candidate the validator decodes obfuscation, skips one optional leading structural " and any leading padding (spaces, NBSP, zero-width, …), then inspects the effective start:

    • ascii — a leading =, +, -, or @ (CWE-1236 / OWASP). The default safety floor; narrowable via ascii_triggers.
    • fullwidth — a leading full-width initiator ＝＋－＠ (OWASP), matched explicitly.
    • control — a leading TAB, CR, or LF (OWASP). A control prefix is itself a trigger, so it is never treated as padding.

    Any leading trigger flags — there is no numeric, function-name, or handle exception (no universal safe-suffix grammar exists), so -5, +1 650 555 0100, and @mention fail by default. A leading ' (the spreadsheet neutralizer) passes. On a hit, the formula_shape detail names a recognized high-impact shape (dde_pipe_bang, hyperlink, dde) so a caller can raise severity on it.

    formula_shape is a best-effort lexical hint, not a formula parser. A recognized shape can over-match a look-alike token inside a string literal (="not really HYPERLINK("). A value of unknown means none of the three recognized shapes matched — it is not a safety signal: other dangerous formulas, including exfiltration functions like =WEBSERVICE(...) and =IMPORTXML(...), report unknown. Use a recognized shape to raise severity; never treat unknown as safe. The marker never changes the verdict, which is already a failure.

    All patterns are linear (no nested quantifier that can backtrack), so the validator adds no ReDoS surface of its own.

    The safety ceiling — read before you rely on this¶

    This validator is defense-in-depth, not a primary control. The authoritative fix is neutralization at the CSV serializer, using a consumer-specific text neutralizer such as a leading ' where the opening application supports it. Ordinary CSV quoting and escaping are not enough: they keep the field structurally intact, but a quoted value like "=1+1" still evaluates as a formula when the file is opened. A guardrail cannot know whether the text will ever become a spreadsheet cell; a passed result means "no leading formula initiator under this policy", never "safe in every spreadsheet".

    On general prose the strict policy's false-positive rate is high — -, +, and @ begin ordinary text constantly. This is the accepted default cost; narrow ascii_triggers (e.g. to "=") for prose-heavy deployments, or use formula_shape to raise severity on a recognized command shape.

    Constructor Parameters¶

    Parameter Type Default Description
    ascii_triggers str "=+-@" Class-A initiators to flag, drawn from =+-@. Narrow it (e.g. "=") to cut the false-positive cost on prose. Must be non-empty and contain only those four characters.
    detect_fullwidth bool True Flag the full-width initiators ＝＋－＠ (class F).
    detect_control_prefix bool True Flag a leading TAB/CR/LF (class C).
    skip_leading_padding bool True Skip leading padding to the effective start before matching, so a padded trigger (" =SUM(...)") is still caught.
    skip_leading_quote bool True Skip one leading structural " before matching, so a quoted "=cmd... is still caught.
    detect_formula_shape bool True Compute the formula_shape severity marker (DDE / HYPERLINK) on a hit.
    strip_invisible_chars bool True Strip zero-width/control characters before matching.
    decode_obfuscation bool True Decode URL/HTML/JS/CSS encoding layers before matching.
    max_input_chars int \| None 1048576 Resource valve (1 MiB of characters by default). When the rendered view exceeds it, the input is rejected with FORMULA_INJECTION_INPUT_TOO_LARGE rather than preprocessed and scanned. Pass None to lift the cap when the input size is already trusted.

    Detection runs per ContentItem, not on the whole view.render(): a formula initiator is position-sensitive (it must be a cell's first character), so each item is treated as one cell candidate. A trigger at the start of any item is caught; a formula-looking substring inside an item (note: =1+1) is not, and an embedded newline (text\n=1+1) is interior, not a new cell.

    Usage¶

    from aegis import Guard
from aegis.validators.detection import FormulaInjectionDetector

guard = Guard("input").use(FormulaInjectionDetector())

result = await guard.validate("=cmd|'/C calc'!A0")
if result.has_failures:
    print(result.failures[0].error_code)  # FORMULA_INJECTION_DETECTED

    Error Codes¶

    Error Code Condition
    FORMULA_INJECTION_DETECTED A content item's effective start is a formula initiator (after decoding, quote/padding skip).
    FORMULA_INJECTION_INPUT_TOO_LARGE max_input_chars is set and the rendered view exceeds it.

    Failure Details¶

    FORMULA_INJECTION_DETECTED reports the earliest offending item (the raw input and matched cell are never echoed):

    Field Type Description
    trigger_class str The trigger class: ascii, fullwidth, or control.
    trigger str The fixed trigger enum: EQUALS, PLUS, MINUS, AT, FULLWIDTH_EQUALS/FULLWIDTH_PLUS/FULLWIDTH_MINUS/FULLWIDTH_AT, or TAB/CR/LF.
    match_offset int Effective-start position, as a count of Unicode code points into the decoded item text (a trigger is a single code point, so no length is reported).
    padding_skipped int Number of leading padding code points skipped to reach the effective start.
    item_index int Index of the offending item in view.items.
    formula_shape str Names a recognized high-impact shape — dde_pipe_bang, hyperlink, or dde — to raise severity on; best-effort lexical match (can over-report a look-alike token). unknown means no recognized shape matched, not that the formula is safe (e.g. =WEBSERVICE(...) reports unknown). Never changes the verdict.

    FORMULA_INJECTION_INPUT_TOO_LARGE carries:

    Field Type Description
    length int The rendered view length that exceeded the limit.
    limit int The configured max_input_chars.

    def __init__(
    self,
    *,
    ascii_triggers: str = "=+-@",
    detect_fullwidth: bool = True,
    detect_control_prefix: bool = True,
    skip_leading_padding: bool = True,
    skip_leading_quote: bool = True,
    detect_formula_shape: bool = True,
    strip_invisible_chars: bool = True,
    decode_obfuscation: bool = True,
    max_input_chars: int | None = _DEFAULT_MAX_INPUT_CHARS,
) -> None:
    """Configure the trigger policy and how aggressively input is decoded before matching.

    The config is narrow by design: the dials narrow or widen the trigger classes and the
    decode/skip passes, but there is no arbitrary user regex or per-value exemption (either would
    reopen a bypass). The ASCII floor cannot be emptied.

    Args:
        ascii_triggers: The class-A initiators to flag, as a string of characters drawn from
            ``=+-@``. Narrow it (e.g. ``"="``) to cut the false-positive cost on prose that leads
            with ``-``/``+``/``@``. Must be non-empty and contain only those four characters.
        detect_fullwidth: Flag the full-width initiators ``＝＋－＠``.
        detect_control_prefix: Flag a leading TAB/CR/LF.
        skip_leading_padding: Skip leading padding (spaces, NBSP, zero-width, …) to the effective
            start before matching, so a padded trigger (``"   =SUM(...)"``) is still caught.
        skip_leading_quote: Skip one leading structural ``"`` before matching, so a CSV-quoted
            field like ``"=1+1`` is still caught (the surrounding quotes are CSV structure, not
            part of the cell content).
        detect_formula_shape: Compute the ``formula_shape`` severity marker (DDE / HYPERLINK) on
            a hit, recorded in ``details`` to raise severity on a recognized shape. A best-effort
            lexical match that can over-report a look-alike token; ``"unknown"`` means no recognized
            shape matched, not that the formula is safe. Never changes the verdict.
        strip_invisible_chars: Strip zero-width/control characters before matching.
        decode_obfuscation: Decode URL/HTML/JS/CSS encoding layers before matching.
        max_input_chars: Resource valve. When the rendered view exceeds it, the input is rejected
            with ``FORMULA_INJECTION_INPUT_TOO_LARGE`` rather than preprocessed and scanned,
            bounding the per-request work (up to ``MAX_DECODE_ITERATIONS`` decode passes per item
            plus a per-character category scan). Defaults to 1 MiB of characters; pass ``None`` to
            lift the cap when the input size is already trusted.

    Raises:
        ValueError: If ``ascii_triggers`` is empty or contains a character outside ``=+-@``, or
            if ``max_input_chars`` is negative.
    """
    # Fail-closed: validate every argument before setting any attribute, so a misconfigured
    # detector raises at construction rather than silently under-enforcing at validate time.
    if not ascii_triggers:
        raise ValueError("ascii_triggers must not be empty; the ASCII safety floor cannot be disabled.")
    invalid = set(ascii_triggers) - _ASCII_TRIGGERS.keys()
    if invalid:
        raise ValueError(f"ascii_triggers may only contain =, +, -, @; got invalid {sorted(invalid)!r}.")
    if max_input_chars is not None and max_input_chars < 0:
        raise ValueError(f"max_input_chars must be non-negative, got {max_input_chars}.")
    self._ascii_triggers = frozenset(ascii_triggers)
    self.detect_fullwidth = detect_fullwidth
    self.detect_control_prefix = detect_control_prefix
    self.skip_leading_padding = skip_leading_padding
    self.skip_leading_quote = skip_leading_quote
    self.detect_formula_shape = detect_formula_shape
    self.strip_invisible_chars = strip_invisible_chars
    self.decode_obfuscation = decode_obfuscation
    self._max_input_chars = max_input_chars

    async def validate(
    self,
    view: ContentView,
    metadata: GuardMetadata | None = None,
) -> ValidationResult:
    """Report whether any content item begins with a spreadsheet formula initiator.

    Inspects each ``ContentItem`` in ``view.items`` as one cell candidate (see the module
    docstring for why this is per-item, not over the flattened ``view.render()``). The resource
    valve measures the rendered length first (the item lengths plus the newline joiners
    ``render()`` would add), before any decoding, so oversized input is rejected without doing the
    per-item decode/scan work — and without materializing the joined string, which the per-item
    scan never needs.

    Args:
        view: The content under inspection. Never ``None``, but may be empty.
        metadata: Surrounding agent context. Optional and unused here.

    Returns:
        ``PassedResult`` when no item's effective start is an enabled trigger. Otherwise a
        ``FailedResult`` carrying ``FORMULA_INJECTION_DETECTED`` for the earliest offending item
        (lowest ``item_index``), with ``details`` holding ``trigger_class``
        (``ascii``/``fullwidth``/``control``), ``trigger`` (the fixed enum, e.g. ``EQUALS``),
        ``match_offset`` (the effective-start position in code points into the decoded item text),
        ``padding_skipped`` (count), ``item_index``, and ``formula_shape``
        (``dde``/``hyperlink``/``dde_pipe_bang``/``unknown``). Or ``FORMULA_INJECTION_INPUT_TOO_LARGE``
        when ``max_input_chars`` is set and the rendered view exceeds it. The raw input, the
        matched cell, and any formula text are never echoed — only the fixed enums, offset, and
        counts are reported.
    """
    # Resource valve. render() joins items with "\n", so the rendered length is the sum of the
    # item lengths plus one "\n" per gap — we compute that directly instead of materializing the
    # whole joined string, which this validator never needs (it scans each item's own value,
    # below). When the cap is lifted (None) we skip the measurement entirely.
    if self._max_input_chars is not None:
        rendered_length = sum(len(item.value) for item in view.items)
        if view.items:
            rendered_length += len(view.items) - 1  # the "\n" joiners render() would insert
        if rendered_length > self._max_input_chars:
            return FailedResult(
                error_message=f"Text exceeds the {self._max_input_chars}-character inspection limit.",
                error_code=self.FORMULA_INJECTION_INPUT_TOO_LARGE,
                details={"length": rendered_length, "limit": self._max_input_chars},
            )

    # The earliest offending item wins: items are scanned in order and the first hit is returned,
    # so the reported item_index is the lowest offending one. Each item is a single cell candidate
    # with one effective start, so exactly one trigger is ever reported — the output stays minimal
    # and never maps out the whole payload.
    for item_index, item in enumerate(view.items):
        hit = _scan_item(
            item.value,
            ascii_triggers=self._ascii_triggers,
            detect_fullwidth=self.detect_fullwidth,
            detect_control_prefix=self.detect_control_prefix,
            skip_leading_padding=self.skip_leading_padding,
            skip_leading_quote=self.skip_leading_quote,
            detect_formula_shape=self.detect_formula_shape,
            strip_invisible=self.strip_invisible_chars,
            decode=self.decode_obfuscation,
        )
        if hit is not None:
            return FailedResult(
                error_message=(
                    f"A content item's effective start is a formula initiator ({hit.trigger_class}) "
                    f"at offset {hit.match_offset}."
                ),
                error_code=self.FORMULA_INJECTION_DETECTED,
                details={
                    "trigger_class": hit.trigger_class,
                    "trigger": hit.trigger,
                    "match_offset": hit.match_offset,
                    "padding_skipped": hit.padding_skipped,
                    "item_index": item_index,
                    "formula_shape": hit.formula_shape,
                },
            )
    return PassedResult()
