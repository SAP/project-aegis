    ContentFilter¶

    Reject text that contains any of a configured list of blocked terms or phrases.

    Description¶

    ContentFilter is a deterministic, text-only, detect-only validator. It runs under Guard as a policy guardrail on agent input or output, scanning the text for a caller-configured list of literal terms and rejecting it when any term appears. Reach for it when you have a known list of words or phrases to keep out — a competitor list, banned subjects, jailbreak markers, or internal code-names.

    Matching is literal, never semantic. Each term is matched as escaped literal text, so the validator finds the exact terms you configure — not a paraphrase, a synonym, a translation, or text that is merely about the subject. Deciding whether text is about a topic without using the words needs a model-backed classifier, which is a separate validator.

    By default a term matches only as a discrete word or phrase, on word boundaries. This avoids the Scunthorpe problem — the classic false positive where a clean word is blocked because a banned string appears inside it. Blocking politics does not reject apolitical; blocking cat does not reject category. The trade-off is that a term embedded inside a longer run of characters is not matched. The boundaries are Python re word-character (\w) boundaries, an approximation of Unicode UAX #29 — reliable for space-delimited scripts. A language that does not delimit words with spaces (Chinese, Thai) needs word_boundary=False, which matches anywhere in the text.

    Normalization is off by default (opt in with normalize=True): matching is fully literal unless you enable it, which mirrors the engine's off-by-default Guard(normalize=...) and keeps matching predictable. When enabled, it folds cheap cosmetic evasions — case changes, added whitespace, zero-width/invisible characters, and NFKC-compatibility variants such as full-width letters (ｇａｍｂｌｉｎｇ → gambling) — by normalizing both the text and every term before matching. These folds are script-safe: they never map homoglyphs (an engine-only concern), so genuine non-Latin letters are not rewritten to ASCII.

    It is not a general safety net, and by design it does not catch:

    • text that is about a blocked subject but never uses a configured term (semantic disclosure);
    • confusable look-alike substitution (Cyrillic о for ASCII o), leetspeak (p0litics), or Base64/hex-encoded terms (documented residual gaps, addressed by future additive hardening);
    • a term split across separately validated messages or chunks.

    Each of those belongs to a different single-concern validator. A PASS certifies only that none of the configured terms appeared — never that the text is on-topic, safe, or lawful. Per OWASP, a denylist is not a general security boundary.

    On a hit the FailedResult carries only safe summary metadata (an opaque term index, a match count, and an offset); it never echoes the surrounding input. The literal blocked term is included only when report_matched_topic=True, which is off by default in case a term is a confidential code-name. If you enable it, or log the failure details, keep confidential values out of blocked_topics.

    Constructor Parameters¶

    Parameter Type Default Description
    blocked_topics list[str] (required) The literal terms/phrases to keep out of the text. At least one is required; each is matched as literal text, never as a regex or a semantic subject.
    word_boundary bool True When True, match only discrete words/phrases on word boundaries (avoids the Scunthorpe false positive). Set False for substring matching — required for Chinese/Thai and other scripts without word delimiters.
    case_sensitive bool False When True, skip case-folding. Only takes effect when normalize=True (case-folding is one step of normalization).
    normalize bool False Opt in to normalize both the text and every term before matching — Unicode normalization, strip zero-width/format characters, collapse whitespace, and case-fold (unless case_sensitive). Off by default: matching is fully literal unless enabled.
    compatibility_folding bool True Only when normalize=True. True uses NFKC, folding full-width and other compatibility variants (catches a real evasion). False uses canonical NFC, avoiding NFKC over-folding but no longer catching full-width forms.
    report_matched_topic bool False When True, include the literal matched_topic in the failure details. Off by default because a configured term could be confidential; the surrounding input is never echoed either way.
    max_input_chars int \| None None Optional resource valve. When set and the rendered text exceeds it, reject with CONTENT_FILTER_INPUT_TOO_LARGE rather than scan. A hard input-size limit belongs to a dedicated length/size validator; this is only a safety valve.

    Construction raises ValueError when blocked_topics is a single string instead of a list (a bare string would expand into one-character terms), when blocked_topics is empty, when any term is empty/whitespace-only or empty after normalization (an empty needle matches everything), or when max_input_chars is negative.

    The defaults suit space-delimited scripts and literal matching. Enable normalize=True for cosmetic-evasion resistance, and calibrate word_boundary and compatibility_folding against your target languages and your own benign and adversarial text before production.

    Usage¶

    The minimal setup blocks a list of words with the safe defaults — word-boundary matching, normalization off (fully literal), nothing echoed:

    from aegis import Guard
from aegis.validators.detection import ContentFilter

guard = Guard("input").use(ContentFilter(blocked_topics=["gambling", "credit card"]))

result = await guard.validate("Come learn about gambling strategies!")
if result.has_failures:
    print(result.failures[0].error_code)  # CONTENT_BLOCKED

    For a Chinese/Thai term, or a deliberate substring policy, opt into substring matching:

    guard = Guard("input").use(
    ContentFilter(blocked_topics=["赌博"], word_boundary=False)
)

result = await guard.validate("这里有很多赌博相关的内容。")
if result.has_failures:
    print(result.failures[0].error_code)  # CONTENT_BLOCKED

    When more than one term matches, the single reported verdict follows a fixed precedence: CONTENT_FILTER_INPUT_TOO_LARGE → CONTENT_BLOCKED. Within CONTENT_BLOCKED, the earliest matching offset wins (ties broken by the term's index in blocked_topics), and match_count reports how many distinct terms matched.

    Error Codes¶

    Error Code Condition
    CONTENT_BLOCKED A configured term appears in the text (as a word-boundary match by default, or anywhere in substring mode).
    CONTENT_FILTER_INPUT_TOO_LARGE max_input_chars is set and the rendered text exceeds it.

    Failure Details¶

    Fields populated on FailedResult.details. They are safe summaries only — never the surrounding input. match_offset indexes the normalized text and is diagnostic only, since the text is never echoed.

    Field Type Description
    matched_index int Opaque index of the matched term within blocked_topics. Reveals nothing about the content.
    match_count int How many distinct configured terms matched at least once.
    match_offset int Character offset of the reported match in the normalized text.
    word_boundary bool Whether word-boundary matching was in effect.
    matched_topic str The literal blocked term — present only when report_matched_topic=True.
    length int Length of the rejected text (only on CONTENT_FILTER_INPUT_TOO_LARGE).
    limit int The configured max_input_chars (only on CONTENT_FILTER_INPUT_TOO_LARGE).

    On a PASS, details carries terms_checked (count of configured terms compared) and word_boundary.

    A deterministic, text-only, detect-only validator. It runs under Guard and scans a piece of text for a caller-configured list of literal terms/phrases, rejecting the text when any term appears as a normalized, word-boundary match (substring matching is opt-in via word_boundary=False). Reach for it as a policy guardrail on agent input or output when you have a known list of words/phrases to keep out — a competitor list, banned subjects, jailbreak markers, internal code-names.

    Matching is literal, never semantic. Each term is matched as escaped literal text — so C++ and a.b match literally, never as a regex — and the validator finds only the exact terms you give it, not a paraphrase, synonym, or translation, and not text that is merely about the subject. Judging whether text is about a topic is the job of a separate, model-backed classifier.

    By default a term matches only as a discrete word or phrase, on word boundaries. This avoids the Scunthorpe false positive — blocking politics does not reject apolitical — at the cost of missing a term embedded without delimiters. The boundaries are Python re word-character (\w) boundaries, an approximation of Unicode UAX #29, so a language such as Chinese or Thai that does not delimit words with spaces needs word_boundary=False.

    Normalization (off by default; opt in with normalize=True) folds cheap cosmetic evasions — case changes, added whitespace, zero-width/invisible characters, and NFKC-compatibility variants such as full-width letters — by normalizing both the text and every term before matching. It does not fold confusable look-alikes, decode Base64/hex, or reverse leetspeak; those are documented residual gaps handled by future, additive hardening (see the ADR).

    Out of scope by design (each is a separate single-concern validator): semantic topic classification, deliberate-obfuscation detection (homoglyphs, leetspeak), encoding/decoding, toxicity/profanity scoring, PII/secret detection, and redacting the term instead of rejecting.

    def __init__(
    self,
    blocked_topics: list[str],
    *,
    word_boundary: bool = True,
    case_sensitive: bool = False,
    normalize: bool = False,
    compatibility_folding: bool = True,
    report_matched_topic: bool = False,
    max_input_chars: int | None = None,
) -> None:
    """Configure the blocked terms and matching behavior.

    Args:
        blocked_topics: The literal terms/phrases to keep out of the text. At least one is
            required, and none may be empty or whitespace-only. Each is matched as literal text
            (regex metacharacters are escaped), never as a pattern or a semantic subject.
        word_boundary: When ``True`` (default), a term matches only as a discrete word/phrase on
            word boundaries, avoiding the Scunthorpe false positive (``politics`` does not match
            ``apolitical``). Set ``False`` for substring matching — required for languages that
            do not delimit words with spaces (Chinese, Thai), where word boundaries are
            unreliable, or for a deliberate substring policy.
        case_sensitive: When ``True``, skip case-folding during normalization. Only takes effect
            when ``normalize=True`` — case-folding is one step of normalization, so with
            ``normalize=False`` matching is fully literal regardless of this flag.
        normalize: When ``True``, normalize both the text and every term before matching —
            Unicode normalization, strip zero-width/format characters, collapse whitespace, and
            case-fold (unless ``case_sensitive``). Defeats cheap cosmetic evasions at the cost
            of some strictness. Defaults to ``False`` (matching is fully literal): opt in
            deliberately, mirroring the engine's off-by-default ``Guard(normalize=...)`` so
            normalization is never applied silently. The folds here are script-safe — they
            never map homoglyphs (that stays an engine-only concern, ``Guard(normalize=True)``),
            so genuine non-Latin letters are not rewritten to ASCII.
        compatibility_folding: Only takes effect when ``normalize=True``. When ``True`` (default),
            use NFKC, which folds full-width and other compatibility variants (``ｇａｍｂｌｉｎｇ`` →
            ``gambling``) — a real, documented evasion. When ``False``, use canonical NFC instead,
            which avoids the UAX #15 over-folding risk but no longer catches full-width forms.
        report_matched_topic: When ``True``, include the literal ``matched_topic`` in the failure
            ``details`` (restores the 0.1.0 proof-of-concept field). Off by default because a
            configured term could be a confidential code-name; the surrounding input is never
            echoed either way.
        max_input_chars: Optional resource valve. When set and the rendered text exceeds it, the
            text is rejected with ``CONTENT_FILTER_INPUT_TOO_LARGE`` rather than scanned. Off by
            default — a hard input-size limit belongs to a dedicated length/size validator; this
            is only a safety valve.

    Raises:
        ValueError: If ``blocked_topics`` is a single string rather than a list (a bare string
            would expand into one-character terms); if ``blocked_topics`` is empty; if any term
            is empty or whitespace-only (an empty needle matches every input and would block
            everything); if any term is empty after normalization; or if ``max_input_chars`` is
            negative (a negative limit exceeds even empty text, so it would reject everything).
    """
    # A bare string is itself iterable, so list("politics") would silently expand to
    # ["p", "o", "l", ...] — one-character terms that over-block almost everything. The
    # list[str] hint is not enforced at runtime (a value from config or JSON can still arrive
    # as a str), so reject it explicitly and fail fast rather than misbehave.
    if isinstance(blocked_topics, str):
        raise ValueError("blocked_topics must be a list of strings, not a single string.")

    topics = list(blocked_topics)

    # Fail closed: with nothing to match against, the validator would silently pass every input —
    # a false sense of security. Reject at construction rather than pass everything.
    if not topics:
        raise ValueError("ContentFilter requires at least one blocked topic in blocked_topics.")

    # An empty or whitespace-only needle is contained in every possible text, so it would reject
    # all input — the documented LLM Guard empty-string bug. Reject it here, reporting the index
    # never the value, in case the value is a confidential term.
    for index, topic in enumerate(topics):
        if not topic.strip():
            raise ValueError(f"blocked_topics[{index}] is empty or whitespace-only.")

    if max_input_chars is not None and max_input_chars < 0:
        # A negative limit makes len(text) > limit true for every candidate — even empty text —
        # so it would reject everything with an impossible bound. Guard it like a real control.
        # (0 is allowed: it means "reject any non-empty text".)
        raise ValueError(f"max_input_chars must be non-negative, got {max_input_chars}.")

    self._word_boundary = word_boundary
    self._report_matched_topic = report_matched_topic
    self._max_input_chars = max_input_chars

    # Build the normalization profile once. ``None`` means "no normalization" — matching is
    # fully literal. Otherwise the script-safe matching profile (NFKC/NFC + strip format chars
    # + collapse whitespace + casefold); compatibility_folding and case_sensitive only take
    # effect here, which is why they are documented as no-ops when normalize is off.
    self._norm_config = (
        NormalizationConfig.for_validators(
            compatibility_folding=compatibility_folding,
            case_sensitive=case_sensitive,
        )
        if normalize
        else None
    )

    # Normalize every term once here, not on each validate() call, since the term list is fixed
    # for the validator's lifetime. A term can survive the empty/whitespace check above yet
    # normalize to nothing (e.g. it was made entirely of zero-width format characters), which
    # would again be a match-everything needle — reject that too, at the one place terms are
    # built. Compile the word-boundary pattern per term now so validate() only runs the search.
    self._blocked: list[_Blocked] = []
    for index, topic in enumerate(topics):
        normalized = self._normalize_text(topic)
        if not normalized:
            raise ValueError(f"blocked_topics[{index}] is empty after normalization.")
        self._blocked.append(
            _Blocked(
                reference_index=index,
                raw=topic,
                normalized=normalized,
                pattern=self._compile_boundary_pattern(normalized) if word_boundary else None,
            )
        )

    async def validate(
    self,
    view: ContentView,
    metadata: GuardMetadata | None = None,
) -> ValidationResult:
    """Inspect the text and report whether it contains any blocked term.

    Scans ``view.render()`` — the whole text, so a Markdown/JSON/code wrapper earns no
    exemption. Since ``render()`` joins parts with a newline, a term spanning a part boundary is
    caught only when that boundary is a whitespace break; a mid-token split is a residual miss
    (see the ADR).

    Returns the single highest-precedence failure (``CONTENT_FILTER_INPUT_TOO_LARGE`` →
    ``CONTENT_BLOCKED``), or ``PassedResult`` if no term matched.

    Args:
        view: The text to inspect as a :class:`ContentView`. Never ``None``; may be empty.
        metadata: Surrounding agent context. Not read by this validator; may be ``None``.

    Returns:
        ``PassedResult`` with ``details = {"terms_checked", "word_boundary"}`` when no term
        matched, or a ``FailedResult`` carrying the ``CONTENT_BLOCKED`` code and a safe-summary
        ``details`` mapping (no surrounding input; the literal term only when
        ``report_matched_topic=True``).
    """
    raw_text = view.render()

    # The size valve runs first: it is both the highest-precedence failure and the point of the
    # cap — reject an oversized candidate before doing any scanning work.
    if self._max_input_chars is not None and len(raw_text) > self._max_input_chars:
        return FailedResult(
            error_code=self.CONTENT_FILTER_INPUT_TOO_LARGE,
            error_message=f"Text exceeds the {self._max_input_chars}-character inspection limit.",
            details={"length": len(raw_text), "limit": self._max_input_chars},
        )

    # Nothing can match in empty or whitespace-only text.
    if not raw_text.strip():
        return self._passed()

    norm_text = self._normalize_text(raw_text)

    # Scan every term and collect the earliest offset each matching term hits at. match_count is
    # the number of *distinct* configured terms that matched at least once — a count, never a
    # list of snippets — and _select picks the single reported verdict deterministically.
    matches = [match for item in self._blocked if (match := self._find(item, norm_text)) is not None]
    winner = self._select(matches)
    if winner is not None:
        return self._to_failure(winner, match_count=len(matches))

    return self._passed()
