    XssDetector¶

    Flag text carrying a known cross-site-scripting (XSS) vector.

    Description¶

    XssDetector is a deterministic, text-only, detect-only validator. It runs under Guard and reports a failure when the content carries a known XSS vector; it never changes the content. Use it as a cheap, non-LLM check at a trust boundary — on model output before it is rendered in a page, or on input that will later be reflected into HTML.

    Guard runs its registered validators concurrently, so a failure here does not short-circuit or skip other validators — "cheap" refers to this validator's own cost.

    Obfuscation is decoded before detection¶

    Real payloads hide behind encoding layers, so the rendered content is preprocessed before any pattern runs: invisible/zero-width control characters are stripped, then URL-percent, HTML-entity, JavaScript \uXXXX/\xXX, and CSS \3C escapes are decoded repeatedly until the text stops changing (bounded). Without this, %3Cscript%3E or &#60;script&#62; would sail past a raw-text matcher. Each pass can be disabled via the constructor when the input's encoding is fully trusted.

    What it flags¶

    • Tag-based markup (html_tag): a complete <tag …> (requiring the closing > ignores benign math/prose such as a < b, a<b, i<n), or an unterminated start tag that already carries a known event-handler attribute (<img src=x onerror=alert(1) with no >) — browsers recover these at EOF so the handler still fires. The handler list is curated, so a benign attribute like online= is not mistaken for a handler.
    • Markup-less vectors that carry no tag:
      • script_uri — javascript: / vbscript: URIs (tolerating the tab/CR/LF a browser strips inside a scheme; a plain space before the colon is not a URL and is not flagged).
      • data_uri — dangerous data: URIs (text/html, application/xhtml+xml, image/svg+xml).
      • css_expression — legacy CSS expression( as a property value (width:expression(…) / style=expression(…)); bare prose like expression(2+2) is not flagged.
      • dom_sink — a write to a DOM sink: .innerHTML / .outerHTML / insertAdjacentHTML on any receiver, or document.cookie|location|write|writeln|domain, as a call ( or an assignment (=, including compound/logical += ??= ||= …). A comparison (==) or arrow (=>) only reads the sink and is not flagged.

    The safety ceiling — read before you rely on this¶

    This validator is defense-in-depth, not a primary control. The authoritative XSS defense is context-aware output encoding at render time. A passed result means "no known XSS marker found", never "provably safe".

    Constructor Parameters¶

    Parameter Type Default Description
    strip_invisible_chars bool True Strip zero-width/control characters before matching.
    decode_obfuscation bool True Decode URL/HTML/JS/CSS encoding layers before matching.
    max_input_chars int \| None None Optional resource valve. When set and the rendered text exceeds it, the text is rejected with XSS_INPUT_TOO_LARGE rather than preprocessed and scanned. Off by default.

    Detection runs on view.render() — the whole flattened ContentView — so a vector split across an item boundary (<scr + ipt>) is still caught, since render() joins items with a newline (matched by \s).

    Usage¶

    from aegis import Guard
from aegis.validators.detection import XssDetector

guard = Guard("input").use(XssDetector())

result = await guard.validate("<script>alert(1)</script>")
if result.has_failures:
    print(result.failures[0].error_code)  # XSS_DETECTED

    Error Codes¶

    Error Code Condition
    XSS_DETECTED The rendered content carries a known XSS vector (after decoding).
    XSS_INPUT_TOO_LARGE max_input_chars is set and the rendered text exceeds it.

    Failure Details¶

    XSS_DETECTED locates the first marker (the raw matched text is never echoed):

    Field Type Description
    match_offset int Start position of the earliest marker, into the decoded/stripped text that was scanned — not the raw input, since decoding shifts offsets.
    match_length int Length of the matched marker.
    vector str The marker class: html_tag, script_uri, data_uri, css_expression, or dom_sink.

    XSS_INPUT_TOO_LARGE carries:

    Field Type Description
    length int The rendered text length that exceeded the limit.
    limit int The configured max_input_chars.

    A detect-only validator for the Guard path. The rendered view is first decoded (see the module docstring) so obfuscated payloads are matched; validate then reports a failure if the content carries an HTML tag (<script>, <img onerror=...>, </div>) or a markup-less vector (javascript: / vbscript: URIs, dangerous data: URIs, CSS expression(), or a DOM-sink call/assignment like document.cookie=).     def __init__(
    self,
    *,
    strip_invisible_chars: bool = True,
    decode_obfuscation: bool = True,
    max_input_chars: int | None = _DEFAULT_MAX_INPUT_CHARS,
) -> None:
    """Configure how aggressively input is decoded before matching.

    The decode/strip passes defeat encoded payloads; a caller who fully trusts the encoding of
    its input (already-decoded, no hostile source) may turn them off to save the work.

    Args:
        strip_invisible_chars: Strip zero-width/control characters before matching.
        decode_obfuscation: Decode URL/HTML/JS/CSS encoding layers before matching.
        max_input_chars: Resource valve. When the rendered text exceeds it, the text is rejected
            with ``XSS_INPUT_TOO_LARGE`` rather than preprocessed and scanned, bounding the
            per-request work (several decode passes plus a per-character category scan).
            Defaults to 1 MiB of characters; pass ``None`` to lift the cap when the input size
            is already trusted.

    Raises:
        ValueError: If ``max_input_chars`` is negative.
    """
    if max_input_chars is not None and max_input_chars < 0:
        raise ValueError(f"max_input_chars must be non-negative, got {max_input_chars}.")
    self.strip_invisible_chars = strip_invisible_chars
    self.decode_obfuscation = decode_obfuscation
    self._max_input_chars = max_input_chars

    async def validate(
    self,
    view: ContentView,
    metadata: GuardMetadata | None = None,
) -> ValidationResult:
    """Report whether the rendered content carries a known XSS vector (after decoding).

    Inspects ``view.render()`` — the whole flattened view — so a vector split across an item
    boundary is still caught (``render()`` joins items with a newline, which ``\\s`` matches).

    Args:
        view: The content under inspection. Never ``None``, but may be empty.
        metadata: Surrounding agent context. Optional and unused here.

    Returns:
        ``PassedResult`` when no XSS vector is found. Otherwise a ``FailedResult`` carrying
        ``XSS_DETECTED`` with ``details`` locating the first marker — ``match_offset`` and
        ``match_length`` (into the decoded/stripped text that was scanned, **not** the raw
        input, since decoding shifts offsets) and ``vector`` (the marker class, e.g.
        ``"html_tag"``, ``"script_uri"``). Or ``XSS_INPUT_TOO_LARGE`` when ``max_input_chars``
        is set and exceeded. The raw input is never echoed; only safe summaries are reported.
    """
    raw_text = view.render()

    if self._max_input_chars is not None and len(raw_text) > self._max_input_chars:
        return FailedResult(
            error_message=f"Text exceeds the {self._max_input_chars}-character inspection limit.",
            error_code=self.XSS_INPUT_TOO_LARGE,
            details={"length": len(raw_text), "limit": self._max_input_chars},
        )

    prepared = preprocess(
        raw_text,
        strip_invisible=self.strip_invisible_chars,
        decode=self.decode_obfuscation,
    )
    match = _find_xss(prepared)
    if match is not None:
        start, end, vector = match
        return FailedResult(
            error_message=f"Input contains a cross-site-scripting (XSS) marker ({vector}) at offset {start}.",
            error_code=self.XSS_DETECTED,
            details={"match_offset": start, "match_length": end - start, "vector": vector},
        )
    return PassedResult()
