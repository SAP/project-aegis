    SqlInjectionDetector¶

    Flag text carrying a known SQL-injection construct.

    Description¶

    SqlInjectionDetector is a deterministic, text-only, detect-only validator. It runs under Guard and reports a failure when the content carries a known SQL-injection construct; it never changes the content. Use it as a cheap, non-LLM check at a trust boundary on text that may reach a query layer.

    Guard runs its registered validators concurrently, so a failure here does not short-circuit or skip other validators — "cheap" refers to this validator's own cost.

    Obfuscation is decoded before detection¶

    Real payloads hide behind encoding layers, so the rendered content is preprocessed before any pattern runs: invisible/zero-width control characters are stripped, then URL-percent, HTML-entity, JavaScript \uXXXX/\xXX, and CSS \3C escapes are decoded repeatedly until the text stops changing (bounded). Without this, a URL-encoded UNION%20SELECT would sail past a raw-text matcher. Each pass can be disabled via the constructor when the input's encoding is fully trusted.

    What it flags¶

    The classic query-breaking constructs — not individual metacharacters (a bare ; or ' would drown callers in false positives on ordinary prose):

    • union_select — UNION SELECT / UNION ALL SELECT extraction.
    • stacked_query — a terminator (;) followed by a complete statement: DROP TABLE, DELETE FROM, TRUNCATE TABLE, ALTER TABLE/DATABASE, CREATE TABLE/…, INSERT INTO <t> with a ( / VALUES / SELECT / SET continuation, UPDATE <t> SET <col>=, or EXEC(/EXEC sp_/ EXEC xp_/EXEC schema.proc. Each keyword is anchored to a word boundary and (for the ambiguous forms) a SQL continuation, so English prose after a semicolon (; create your profile, ; delete fromagerie, ; insert into the box) is not flagged.
    • tautology — an always-true equal-operands comparison with OR or AND (boolean-blind): ' OR '1'='1, 0 OR '1'='1', OR 1=1, AND 1=1. A false comparison ('admin'='guest', 1=2, '1'='10') and benign arithmetic (2 or 3 = 5) are not flagged.
    • comment_tail / block_comment — SQL comments: a /* opener, or a --/# tail after a quote or terminator ('--, ; --).
    • time_based_probe — blind probes with a numeric argument: SLEEP(5), pg_sleep(10), BENCHMARK(n,…), or WAITFOR DELAY. (A numeric arg keeps sleep (now) prose from matching.)

    Every pattern is linear (no nested quantifier that can backtrack), so the validator adds no ReDoS surface of its own.

    The safety ceiling — read before you rely on this¶

    This validator is defense-in-depth, not a primary control. The authoritative SQL-injection defense is parameterized queries (prepared statements) — never string-concatenated SQL. A passed result means "no known injection marker found", never "provably safe".

    Constructor Parameters¶

    Parameter Type Default Description
    strip_invisible_chars bool True Strip zero-width/control characters before matching.
    decode_obfuscation bool True Decode URL/HTML/JS/CSS encoding layers before matching.
    max_input_chars int \| None None Optional resource valve. When set and the rendered text exceeds it, the text is rejected with SQLI_INPUT_TOO_LARGE rather than preprocessed and scanned. Off by default.

    Detection runs on view.render() — the whole flattened ContentView — so a construct split across an item boundary (1 UNION + SELECT …) is still caught, since render() joins items with a newline (matched by \s).

    Usage¶

    from aegis import Guard
from aegis.validators.detection import SqlInjectionDetector

guard = Guard("input").use(SqlInjectionDetector())

result = await guard.validate("1 UNION SELECT password FROM users")
if result.has_failures:
    print(result.failures[0].error_code)  # SQLI_DETECTED

    Error Codes¶

    Error Code Condition
    SQLI_DETECTED The rendered content carries a known SQL-injection construct (after decoding).
    SQLI_INPUT_TOO_LARGE max_input_chars is set and the rendered text exceeds it.

    Failure Details¶

    SQLI_DETECTED locates the first construct (the raw matched text is never echoed):

    Field Type Description
    match_offset int Start position of the earliest construct, into the decoded/stripped text that was scanned — not the raw input, since decoding shifts offsets.
    match_length int Length of the matched construct.
    construct str The construct class: union_select, stacked_query, tautology, block_comment, comment_tail, or time_based_probe.

    SQLI_INPUT_TOO_LARGE carries:

    Field Type Description
    length int The rendered text length that exceeded the limit.
    limit int The configured max_input_chars.

The rendered view is first decoded (see the module docstring) so obfuscated payloads are matched; validate then reports a failure if the content carries a known SQL-injection marker — UNION SELECT, a stacked ; DROP TABLE query, a tautology (' OR '1'='1, OR 1=1), a SQL comment (/*!, '--), or a time-based blind probe (sleep() / benchmark() / WAITFOR DELAY).     def __init__(
    self,
    *,
    strip_invisible_chars: bool = True,
    decode_obfuscation: bool = True,
    max_input_chars: int | None = _DEFAULT_MAX_INPUT_CHARS,
) -> None:
    """Configure how aggressively input is decoded before matching.

    The decode/strip passes defeat encoded payloads; a caller who fully trusts the encoding of
    its input (already-decoded, no hostile source) may turn them off to save the work.

    Args:
        strip_invisible_chars: Strip zero-width/control characters before matching.
        decode_obfuscation: Decode URL/HTML/JS/CSS encoding layers before matching.
        max_input_chars: Resource valve. When the rendered text exceeds it, the text is rejected
            with ``SQLI_INPUT_TOO_LARGE`` rather than preprocessed and scanned, bounding the
            per-request work (up to ``MAX_DECODE_ITERATIONS`` decode passes plus a per-character
            category scan). Defaults to 1 MiB of characters; pass ``None`` to lift the cap when
            the input size is already trusted.

    Raises:
        ValueError: If ``max_input_chars`` is negative.
    """
    if max_input_chars is not None and max_input_chars < 0:
        raise ValueError(f"max_input_chars must be non-negative, got {max_input_chars}.")
    self.strip_invisible_chars = strip_invisible_chars
    self.decode_obfuscation = decode_obfuscation
    self._max_input_chars = max_input_chars

    async def validate(
    self,
    view: ContentView,
    metadata: GuardMetadata | None = None,
) -> ValidationResult:
    """Report whether the rendered content carries a known SQL-injection construct.

    Inspects ``view.render()`` — the whole flattened view — so a construct split across an item
    boundary is still caught (``render()`` joins items with a newline, which ``\\s`` matches).

    Args:
        view: The content under inspection. Never ``None``, but may be empty.
        metadata: Surrounding agent context. Optional and unused here.

    Returns:
        ``PassedResult`` when no injection marker is found. Otherwise a ``FailedResult``
        carrying ``SQLI_DETECTED`` with ``details`` locating the first construct —
        ``match_offset`` and ``match_length`` (into the decoded/stripped text that was scanned,
        **not** the raw input, since decoding shifts offsets) and ``construct`` (the construct
        class, e.g. ``"union_select"``, ``"stacked_query"``). Or ``SQLI_INPUT_TOO_LARGE`` when
        ``max_input_chars`` is set and exceeded. The raw input is never echoed; only safe
        summaries are reported.
    """
    raw_text = view.render()

    if self._max_input_chars is not None and len(raw_text) > self._max_input_chars:
        return FailedResult(
            error_message=f"Text exceeds the {self._max_input_chars}-character inspection limit.",
            error_code=self.SQLI_INPUT_TOO_LARGE,
            details={"length": len(raw_text), "limit": self._max_input_chars},
        )

    prepared = preprocess(
        raw_text,
        strip_invisible=self.strip_invisible_chars,
        decode=self.decode_obfuscation,
    )
    match = _find_sqli(prepared)
    if match is not None:
        start, end, construct = match
        return FailedResult(
            error_message=f"Input contains a SQL-injection construct ({construct}) at offset {start}.",
            error_code=self.SQLI_DETECTED,
            details={"match_offset": start, "match_length": end - start, "construct": construct},
        )
    return PassedResult()
