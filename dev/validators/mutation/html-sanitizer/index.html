    HtmlSanitizer¶

    Reduce HTML content to a safe, allowlisted subset — removing scripts, event handlers, dangerous URLs, and disallowed markup.

    Mutation is supported, with a caveat

    Under the Detection vs. Mutation rule, XSS / HTML-stripping is a security concern that normally should detect-and-reject rather than repair. HtmlSanitizer is an exception: it is a thin wrapper over the well-tested nh3/ammonia sanitizer, so repairing content is safe and the mutation path is kept. If you prefer to reject unsafe content outright instead of silently repairing it, run it under Guard (detect-only, blocking on failure).

    Description¶

    HtmlSanitizer treats each content part as an HTML fragment and enforces an allowlist of tags, attributes, URL schemes, and (optionally) inline-CSS properties. Everything outside the allowlist — <script>, event-handler attributes such as onerror, javascript: URLs, HTML comments, unknown tags — is removed, and the result is re-serialized from a spec-compliant parse tree. It defends against cross-site scripting (CWE-79) and mutation-XSS when agent content may later be rendered as HTML by a downstream client.

    It is a detect-and-fix validator: run it under MutationGuard to repair content, or under Guard for detect-only (rejecting anything not already in canonical, allowlisted form). Detection and repair share one definition of safe — a part is acceptable exactly when it already equals its sanitized form — so validate reports a change and mutate emits the sanitized text.

    The sanitizer is powered by nh3 (the Rust ammonia library over html5ever). Because it parses input into a tree and re-serializes, it resists syntactic obfuscation: mixed case (<ScRiPt>), HTML entities (&#106;avascript:), and malformed nesting are all resolved to the canonical tree before the allowlist is applied.

    HTML only — not for plain text

    Apply this only to content meant to be rendered as HTML. A stray < or > in plain text (for example 5 < 3) is HTML-escaped, which changes the text and is reported as a violation. Deciding whether content should be HTML at all is the caller's routing decision.

    Widening the allowlist enlarges the attack surface

    The defaults are safe: HTML-only, tightened URL schemes, inline CSS disabled. Two options are especially load-bearing — adding foreign-content tags (svg, math, foreignObject) reopens namespace-confusion vectors, and enabling inline CSS is only as safe as the property list you allow.

    Constructor Parameters¶

    Parameter Type Default Description
    allowed_tags set[str] \| None None (nh3's HTML-only default) Permitted tag names. A set replaces the default rather than adding to it.
    allowed_attributes dict[str, set[str]] \| None None (nh3's per-tag default) Attributes permitted per tag ("*" key = any tag). Replaces the default entirely and is honored as given — a custom allowlist that lists an event handler (e.g. onclick) keeps it, so widen only for trusted content.
    allowed_url_schemes set[str] \| frozenset[str] {http, https, mailto} Schemes permitted in URL-bearing attributes. javascript: and data: are excluded.
    allowed_css_properties set[str] \| frozenset[str] \| None None (inline CSS disabled) Inline-CSS properties permitted in style. None removes style entirely, even if allowed in allowed_attributes.
    strip_comments bool True Remove HTML comments (they can leak metadata).
    link_rel str \| None "noopener noreferrer" rel value forced onto <a> (mitigates reverse-tabnabbing). None leaves rel untouched.

    Usage¶

    from aegis import MutationGuard
from aegis.validators.mutation import HtmlSanitizer

guard = MutationGuard("output").use(HtmlSanitizer())
result = await guard.validate("<script>alert(1)</script>Hello")

if result.was_mutated:
    print(result.output)  # "Hello"

    Enabling inline CSS is opt-in. Start from a vetted property set rather than allowing arbitrary properties, and remember style must also be listed in allowed_attributes:

    sanitizer = HtmlSanitizer(
    allowed_tags={"p", "span"},
    allowed_attributes={"p": {"style"}, "span": {"style"}},
    allowed_css_properties={"color", "font-weight", "text-align"},
)

    nh3 sanitizes CSS values too — a url() with a disallowed scheme is dropped even on an allowed property. Two residuals are worth knowing. First, behavior and -moz-binding load script through a url() that this value-level filtering does not catch, so do not allowlist them. Second, the legacy IE expression() function is not stripped by nh3, but it is inert in every browser from IE8 (2009) onward and is treated as an accepted out-of-scope non-goal.

    Error Codes¶

    Error Code Condition
    DISALLOWED_HTML At least one part differs from its sanitized form — it carried disallowed or non-canonical markup.

    Failure Details¶

    Fields populated on FailedResult.details. Only safe summaries are reported — never the raw markup, which could carry an XSS payload or an embedded secret.

    Field Type Description
    changed_parts int Number of content parts that differed from their sanitized form.
    original_length int Summed character length of the offending parts, before sanitization.
    sanitized_length int Summed character length of those parts after sanitization.

Detection and repair share one definition of "safe": a part is acceptable exactly when it already equals its sanitized form.

    • validate sanitizes each part and compares it to the original. Any difference means the part carried disallowed or non-canonical markup, so it returns a :class:FailedResult with :attr:DISALLOWED_HTML.

Deciding whether content should be HTML at all is the caller's routing decision, not this validator's job.

    Safe defaults, widen at your own risk. Out of the box the policy is HTML-only with a tightened URL-scheme set and inline CSS disabled. Every constructor parameter that widens the allowlist enlarges the attack surface; two are especially load-bearing:

    1. Adding foreign-content tags (svg, math, foreignObject) reopens namespace-confusion vectors that the HTML-only default avoids.
    2. Enabling inline CSS (allowed_css_properties) is only as safe as the property list you allow — see that parameter's documentation.

    def __init__(
    self,
    *,
    allowed_tags: set[str] | None = None,
    allowed_attributes: dict[str, set[str]] | None = None,
    allowed_url_schemes: set[str] | frozenset[str] = DEFAULT_ALLOWED_URL_SCHEMES,
    allowed_css_properties: set[str] | frozenset[str] | None = None,
    strip_comments: bool = True,
    link_rel: str | None = "noopener noreferrer",
) -> None:
    self._tags = allowed_tags
    self._url_schemes = set(allowed_url_schemes)
    self._css_properties = set(allowed_css_properties) if allowed_css_properties is not None else None
    self._strip_comments = strip_comments
    self._link_rel = link_rel

    # A caller-supplied ``allowed_attributes`` replaces the default entirely and is
    # honored as given — the same contract ``allowed_tags`` and ``allowed_url_schemes``
    # follow. Safety comes from the safe defaults, not from silently overriding an
    # explicit request. Three cases:
    # 1. A tag→attributes mapping is kept as passed. If a caller allowlists an event
    #    handler such as ``onclick`` it stays — their explicit choice, no different
    #    from allowlisting the ``javascript`` scheme or the ``iframe`` tag.
    # 2. ``style`` is the one exception, and it is parameter precedence rather than an
    #    override: inline CSS is controlled solely by ``allowed_css_properties``, so
    #    when that is None (CSS off) a ``style`` entry here is dropped. Otherwise nh3
    #    with no property filter would allow *every* CSS property, silently enabling
    #    unfiltered inline CSS the caller did not ask for. Matched case-insensitively,
    #    since HTML attribute names are.
    # 3. ``None`` passes straight to nh3, whose per-tag default contains no event
    #    handlers.
    if allowed_attributes is not None and self._css_properties is None:
        self._attributes: dict[str, set[str]] | None = {
            tag: {attr for attr in attrs if attr.lower() != "style"} for tag, attrs in allowed_attributes.items()
        }
    else:
        self._attributes = allowed_attributes

    async def validate(self, view: ContentView, metadata: GuardMetadata | None = None) -> ValidationResult:
    """Report whether every part is already in its sanitized form.

    Each part is sanitized independently and compared to the original. We
    compare against the sanitized form rather than trying to recognize "bad"
    markup directly: the allowlist is the only arbiter of safety, so anything
    the sanitizer would change — a disallowed tag, a dropped attribute, or even
    benign normalization such as closing an open tag — is treated as a
    violation to repair. This favors safety over precision; for a mutation
    validator the cost of a benign-normalization "false" failure is nil, since
    ``mutate`` simply emits the already-canonical form.

    Args:
        view: The content under inspection. Each item is treated as an
            independent HTML fragment.
        metadata: Surrounding agent context. Unused — the sanitizer governs
            markup only, never the meaning of the prose.

    Returns:
        :class:`PassedResult` when every part equals its sanitized form,
        otherwise a :class:`FailedResult` with ``error_code``
        :attr:`DISALLOWED_HTML`. The ``details`` mapping carries only safe
        summaries — ``changed_parts`` and the summed ``original_length`` /
        ``sanitized_length`` — never the raw markup, which could contain an
        XSS payload or an embedded secret.
    """
    changed_parts = 0
    original_length = 0
    sanitized_length = 0
    for part in view.items:
        sanitized = self._clean(part.value)
        if sanitized != part.value:
            changed_parts += 1
            original_length += len(part.value)
            sanitized_length += len(sanitized)

    if changed_parts:
        details: dict[str, Any] = {
            "changed_parts": changed_parts,
            "original_length": original_length,
            "sanitized_length": sanitized_length,
        }
        return FailedResult(
            error_code=self.DISALLOWED_HTML,
            error_message="Content contains disallowed or non-canonical HTML markup.",
            details=details,
        )
    return PassedResult()

    mutate(view, metadata=None, validation_failure=None) async ¶

    Return the sanitized form of each part that is not already clean.

    Only parts that actually change are addressed; an unchanged part is left alone, which keeps the edit set minimal and lets the engine report was_mutated=False when nothing needed fixing.

    The output is safe to re-validate: feeding it back through validate yields :class:PassedResult, because sanitizing already-sanitized content is a no-op (clean(clean(x)) == clean(x)). This fixed-point property is what lets the mutation path be trusted, and is enforced by the test suite.

    async def mutate(
    self,
    view: ContentView,
    metadata: GuardMetadata | None = None,
    validation_failure: FailedResult | None = None,
) -> list[ItemEdit]:
    """Return the sanitized form of each part that is not already clean.

    Only parts that actually change are addressed; an unchanged part is left
    alone, which keeps the edit set minimal and lets the engine report
    ``was_mutated=False`` when nothing needed fixing.

    The output is safe to re-validate: feeding it back through ``validate``
    yields :class:`PassedResult`, because sanitizing already-sanitized content
    is a no-op (``clean(clean(x)) == clean(x)``). This fixed-point property is
    what lets the mutation path be trusted, and is enforced by the test suite.

    Args:
        view: The content to repair.
        metadata: Surrounding agent context. Unused.
        validation_failure: The failure from ``validate``. Unused — ``mutate``
            recomputes the sanitized form directly rather than depending on the
            detection details.

    Returns:
        One :class:`ItemEdit` per changed part, addressed by part id.
    """
    edits: list[ItemEdit] = []
    for part in view.items:
        sanitized = self._clean(part.value)
        if sanitized != part.value:
            edits.append(ItemEdit(part.id, sanitized))
    return edits
